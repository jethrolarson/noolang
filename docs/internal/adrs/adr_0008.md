# 8. Tail-position trampolining, not CPS or a bytecode VM, for TCO

Date: 2026-08-30

## Status

Accepted, implemented (`src/evaluator/evaluator.ts`:
`evaluateTailPosition`, `runTrampolined`; `FunctionValue.tailInfo` in
`evaluator-utils.ts`).

## Context

The evaluator is tree-walking, one JS call per noolang call
(`evaluateExpression` → `evaluateApplication` → closure `.fn(arg)` → ...).
Self-tail-recursive call chains overflowed the JS stack at ~10,000-11,000
depth (measured). Hit in practice: `std/parser.noo`'s `many`-based
combinators and `std/json.noo`'s string parser (worked around in PR #188
with a `reduce`-based scanner instead of the idiomatic combinator form).

Two heavier alternatives — CPS-rewriting the evaluator so every call
trampolines uniformly, or compiling to bytecode with an explicit call
stack (filed separately, not started:
`docs/internal/ideas/BYTECODE_VM_REWRITE.md`) — both replace execution
semantics for effects/trait dispatch/closures wholesale. Neither was
needed to fix ordinary tail recursion overflowing.

## Decision

`evaluateTailPosition`: a syntactic tail-position dispatcher, plain JS
recursion (bounded by a body's *static* nesting, not call count) through
`if`/`match`/`where`'s main expression/`;`/single-step `pipeline`/
`typed`/`constrained`. At `application`, a saturated call into a
same-owner terminal closure (`FunctionValue.tailInfo`) returns a
`TailCall` marker instead of invoking `.fn`; `runTrampolined` loops on it
in one JS frame per logical call.

**Syntactic, not semantic.** `$`, `|`, and `&&`/`||`'s evaluated branch are
real tail positions too, deliberately out of scope — a reviewable
boundary, not an oversight.

**Owner-gated.** Each imported module has its own `Evaluator`
(`src/module-loader.ts`). A tail call into a different evaluator's closure
always falls through to a normal `.fn` call — bouncing would run the
callee under the caller's trait registry/environment/`currentFileDir`,
corrupting relative-import resolution and trait dispatch.

**Duplicated, not shared, dispatch logic.** Doesn't call into
`evaluateIf`/`evaluateMatch`/`evaluateWhere`/`evaluateApplication` —
checked, not assumed: an earlier version shared helpers with them, and the
one added JS frame per extraction alone overflowed an already-borderline
test (`std/json.noo`'s long-string parse, the original symptom). Reverted;
duplication is the accepted cost.

## Consequences

- Self-tail-recursive functions stack-safe at effectively unbounded depth
  (verified to 500,000 calls, ~1.5s) instead of overflowing at
  ~10,000-11,000.
- No measurable regression on non-tail workloads (`fib 27`, ~832k calls,
  within noise before/after) despite every terminal-closure call now
  routing through the new dispatcher.
- `where`-scoped recursive bindings (self or mutual) remain broken,
  independent of this change — `evaluateWhere` never Cell-wraps its own
  definitions the way top-level `=` does. A separate letrec feature if
  wanted.
- True mutual recursion between top-level bindings doesn't work either
  (confirmed during test design) — same class of gap, also untouched.
- Drift risk: a future change to the four non-tail methods above can
  silently desync from `evaluateTailPosition`'s mirrored logic; only a
  same-file comment on each case points back, nothing enforced.
- Not done here: reverting `std/json.noo`'s `reduce`-based
  `json_string_body_p` to the plain `many`-based combinator form now that
  this should round-trip cleanly — worth a follow-up PR.
