# 10. Prototype a kinded constructor core before shipping trait-slot syntax

Date: 2026-09-02

## Status

Proposed; prototype-gated. Supersedes ADR 0009 only if the prototype meets the
acceptance criteria below.

## Context

Noolang represents `f a` in `Functor f` as a `VariantType` whose lowercase name
stands for a constructor variable. The typer then recovers facts absent from that
representation: whether the name is nominal or variable, constructor arity,
which concrete arguments `f` models, and how those arguments survive
substitution and module transport. `List` additionally crosses canonical
`ListType` and synthetic-variant paths.

PR #194 implemented ADR 0009's explicit `_` slots correctly enough to serve as
an executable specification. Review nevertheless found successive independent
gaps in lambda wrappers, fixed arguments sharing free variables, `_` escaping
into ordinary annotations, and nested holes registering before failing at
dispatch. This is evidence that the representation, not only individual fixes,
is creating a broad correctness surface. `_` also conventionally means
"discarded" while an implementation-head hole is the decisive modeled slot.

Type lambdas are interesting here only if they expose a smaller honest core.
Adding lambda syntax that compiles into all existing special cases would add a
system rather than simplify one. Noolang's direct, tag-based effect system is a
separate design and remains unchanged.

## Decision

Before merging ADR 0009's surface syntax, prototype a compile-time constructor
calculus with:

- kinds `Type` and `k1 -> k2`;
- distinct representations for type variables, nominal constructors, and type
  application;
- explicit constructor abstraction sufficient to express, provisionally,
  `typefn value => Result value error`;
- beta-reduction before ordinary unification; and
- nominal runtime instance identity and coherence.

The prototype is deliberately not general higher-order inference. Constructor
abstractions are explicit; their parameters range over `Type`; trait constructor
parameters have one fixed kind; unknown type-level functions are not inferred;
and lambdas may not escape into higher-rank or kind-polymorphic positions.
Initially an implementation abstraction must reduce to a saturated allowed
nominal constructor (`variant` or intrinsic `List`), use every bound parameter
exactly once as a direct constructor argument, and leave erased aliases and
structural types ineligible for instance identity. Arity-zero value traits and
primitive instances retain their current meaning.

Surface spelling is not decided by this ADR. `typefn` is a prototype notation
because it distinguishes erased constructor abstraction from runtime `fn`; the
prototype must not make it permanent accidentally.

Accept the redesign only if the spike demonstrates a net conceptual reduction:
constructor arity is kind-checked; local and imported dispatch share one
application/substitution model; and the production design can remove lowercase
fake-variant detection, `traitConstraint` metadata on variants, positional
append/slice reconstruction, and trait-specific `List` normalization rather
than retaining them underneath the new model. PR #194's positive, negative,
wrapper, fixed/free, and module tests are the behavioral baseline. Exact inferred
argument order is mandatory.

## Consequences

The spike may conclude that ADR 0009's bounded descriptor is cheaper; that is a
valid result if the proposed core cannot delete the listed special machinery.
A successful spike informs a replacement implementation ADR and migration plan,
not an automatic production merge.

No constructor composition, reusable higher-kinded aliases, generic
`traverse`/`sequence` APIs, overlapping instances, effect redesign, or runtime
type-lambda values are included. Those remain future features requiring their
own demonstrated use and decisions.

PR #194 is parked as reference and test evidence while this decision is open.
